# First-Hit Studio 3.0 / 数位首现汇聚谱

**Android 原生应用**。无 WebView、无浏览器任务调度、无预设搜索小数位数上限。

## 数学定义

令 x_i = sqrt(n_i)，n_i 为从 2 开始依次排列的非完全平方正整数。给定目标十进制数字串 w、出现序号 r、样本数 N，设 T_{w,r}(x_i) 是 w 在 x_i 小数展开中第 r 次出现的首位位置。对有定义的完成样本，计算

    F_N(w,r) = (1/N) * Σ_{i=1..N} T_{w,r}(x_i)

**重叠匹配计数**。例：`111` 中 `11` 在第 1 位和第 2 位各出现一次。

某个数字串未必能被数学上保证出现在每个无理数中；因此本应用**不把未完成的样本当成“没有出现”**，也不以任意固定精度截断。搜索持续至达到指定出现次数，或由用户暂停 / 中止。中止后的统计明确标记为 **部分样本**，不伪装成完整 N 样本统计。

## 算法

- 使用 `java.math.BigInteger` 平方根整数部分 Newton 法与基于 100 的逐位长除法，得到**精确的十进制小数位**。
- 使用 KMP 进行任意长度数字串的在线匹配，统计第 r 次（支持重叠），无预设搜索位数上限。
- 原生 Java `ExecutorService` 使用可用 CPU 核心并行计算各个独立样本；批次按样本顺序汇总，累计均值严格按索引定义更新。
- CSV 每批流式写入应用私有文件，故完整原始记录**不会因为图表为性能做抽样而丢失**。图表最多保留几千个采样点，但均值和 CSV 始终包含所有已完成样本。
- 用户可以输入任意长度数字串，出现次数和样本数采用 BigInteger。没有用户界面设置的数字上限，但手机仍有有限 CPU、内存、存储及系统资源，极大任务可能很慢或失败。
- 默认演示曲线来自此前验证的 N=10000、w=1、r=1 的实际实验：sum=102187，mean=10.2187。演示图并不替代启动后的新计算。

## 页面设计

Modernist editorial / 现代主义编辑风格：暖白底、深墨色块、克制钴蓝色、橘色理论基线；定制 Canvas 主图与近端放大图均采用**16:10**，其他 UI 随手机纵向屏幕自适应。卡片和内容的入场动效、原生走势图绘制、手势探查和触控参数控制均不依赖浏览器。

## 编译

1. 用 Android Studio 打开项目根目录 `first-hit-native-v3`。
2. 同步 Gradle（Android Gradle Plugin 8.7.3，JDK 17，compileSdk 35，minSdk 26）。
3. Build → Build APK(s)，将 `app/build/outputs/apk/debug/app-debug.apk` 安装到 Android 8.0+ 设备。

本环境不自带 Android SDK，因此如果没有来自 GitHub Actions 的成功构建结果，不应宣称 APK 已经过真机安装验证。

## 数据的严格性

动画和可视化可以随帧抽样；但数值平均、结果数量、CSV 文件逐项完整。计算中所有未完成样本显示为“仍在搜索”，不会出现之前错误的“截至 500 位未找到”而丢失样本。

## 技术说明

长任务请在前台保持 APP 开启；目前后台长期运行尚未接入 Android 前台服务，操作系统可能暂停或结束退入后台的任务。Android 上也不能保证始终保持所有核心在最高频率（受热管理和功耗管理影响）。
